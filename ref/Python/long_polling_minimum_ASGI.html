ロングポーリング構成

nginx · ASGI (Daphne) · Python (ProtocolTypeRouter)

全体構成図

タイムアウトの大小関係

内側から順にタイムアウトするよう設定する。外側が先に切断すると、内側の処理が宙に浮いたまま残る。

nginx 設定

nginx

1プロセス（Daphne）だけに転送する。パスで /poll/ とその他を分けてタイムアウトを変える。

upstream django {
    server 127.0.0.1:8000;  # Daphne の 1 プロセスのみ
}

server {
    listen 80;

    # ロングポーリング専用 — タイムアウト長め、バッファ無効
    location /poll/ {
        proxy_pass         http://django;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host       $host;
        proxy_read_timeout 90s;
        proxy_buffering    off;
    }

    # 通常リクエスト — タイムアウト短め
    location / {
        proxy_pass         http://django;
        proxy_http_version 1.1;
        proxy_set_header   Host       $host;
        proxy_set_header   X-Real-IP  $remote_addr;
        proxy_read_timeout 10s;
    }
}

ASGI 設定（asgi.py）

ASGI

ProtocolTypeRouter で /poll/ を非同期ビューへ、それ以外を既存の WSGIHandler へ委譲する。

import os
from django.core.asgi import get_asgi_application
from django.core.handlers.wsgi import WSGIHandler
from channels.routing import ProtocolTypeRouter, URLRouter
from asgiref.wsgi import WsgiToAsgi
from django.urls import path
from myapp.async_views import long_poll_view

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
wsgi_app = WsgiToAsgi(WSGIHandler())  # 既存 WSGI アプリを ASGI にラップ。ミドルウェアも呼ぶ。コード変更なし

application = ProtocolTypeRouter({
    'http': URLRouter([
        path('poll/<str:job_id>/', long_poll_view),
        path('<path:path>', wsgi_app),
        path('',             wsgi_app),
    ]),
})

Python — 非同期ビュー（async_views.py）

Python

待機部分だけが非同期。完了通知を受けたら既存の WSGI ビューを sync_to_async で同期的に呼び出す。

import asyncio
from asgiref.sync import sync_to_async
from myapp.models import Job
from myapp.views  import existing_wsgi_view  # 既存コードそのまま

async def long_poll_view(request, job_id):

    # 非同期で完了を待つ（イベントループをブロックしない）
    await wait_for_job(job_id)

    # 完了後、既存の WSGI ビューを同期的・排他的に呼び出す
    return await sync_to_async(
        existing_wsgi_view,
        thread_sensitive=True,  # 同じスレッドで実行
    )(request)


async def wait_for_job(job_id):
    # DBポーリング（1秒間隔、最大30秒）
    for _ in range(30):
        get_job = sync_to_async(Job.objects.get)
        job = await get_job(id=job_id)
        if job.status == 'completed':
            return
        await asyncio.sleep(1)
    raise TimeoutError()

コールツリー

long_poll_view(request, job_id)        # ASGI・非同期
├── wait_for_job(job_id)               # 非同期待機（ノンブロッキング）
│   ├── sync_to_async(Job.objects.get) # DB確認（非同期ラップ）
│   └── asyncio.sleep(1)              # 非同期スリープ
└── sync_to_async(existing_wsgi_view)  # 待機完了後、同期コードを呼び出す
    └── existing_wsgi_view(request)    # 既存 WSGI コード（変更なし）
        └── Job.objects.get(...)       # 同期 DB アクセス

レイヤー 設定項目 推奨値 備考
Django asyncio.sleep × 30回 30秒 DBポーリング合計待機時間
Gunicorn（参考） --timeout 45秒 WSGI 側。今回の構成では Daphne が担う

ASGI と WSGI の振り分け

振り分けは nginx のパス設定と Python の ProtocolTypeRouter が担う。Python コードの中で明示的に ASGI/WSGI を区別する必要はない。

WSGI → ASGI 移植時の注意点

注意点 対策
同期 DB アクセス sync_to_async でラップする
同期ミドルウェア 非同期対応に書き直すか、WSGI 側に残す
スレッドローカル変数 contextvars.ContextVar に置き換える
ブロッキングライブラリ（requests 等） httpx / aiohttp などの非同期版に替える
同期デコレーター（@login_required 等） ミドルウェアか自前の認証チェックに替える
ロングポーリング以外のリクエストは既存 WSGI コードをそのまま使うため、上記の注意点は long_poll_view と wait_for_job の中だけに適用すれば済む。
